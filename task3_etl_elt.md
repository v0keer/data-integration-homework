\# Задание 3. Выбор подхода ETL или ELT



| № | Пара «источник — приёмник» | Подход | Обоснование |

|---|---------------------------|--------|-------------|

| 1 | БД каталога → Корзина | \*\*ETL\*\* | Малый объём, простые преобразования, данные временные. Преобразование до загрузки экономит ресурсы. |

| 2 | Форма сайта → БД заказов | \*\*ETL\*\* | Структурированные данные, нужна валидация до записи, транзакции. |

| 3 | БД заказов сайта → OMS | \*\*ETL\*\* | Операционная система, важна целостность, объёмы небольшие, преобразования простые. |

| 4 | OMS → Платёжный шлюз | \*\*ETL\*\* | Данные конфиденциальны (PII, карты), нужно маскирование до отправки. |

| 5 | Платёжный шлюз → OMS | \*\*ETL\*\* | Малый объём, простые данные, важна скорость. |

| 6 | OMS → WMS | \*\*ETL\*\* | Структурированные данные, объёмы средние, преобразования простые. |

| 7 | WMS → Курьерская служба | \*\*ETL\*\* | Внешний API, лимиты на запросы, нужно преобразование форматов до отправки. |

| 8 | Курьерская служба → OMS | \*\*ETL\*\* | Малый объём, простые данные, важна актуальность. |



\## Вывод



Для данного бизнес-процесса \*\*преобладает ETL\*\*, потому что:

\- Объёмы данных небольшие и средние.

\- Много внешних систем с API и лимитами.

\- Требуется маскирование конфиденциальных данных (PII, платёжные данные).

\- Операционные системы требуют целостности и валидации до загрузки.



\*\*ELT\*\* был бы уместен, если бы мы строили аналитическое хранилище (например, для аналитики продаж), где можно загружать сырые данные и преобразовывать внутри.
