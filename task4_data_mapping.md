# Задание 4. Объект данных «Клиент» и карта сопоставления

## Выбранный объект данных
**Клиент** (передаётся из сайта интернет-магазина в OMS)

## Структура объекта в источнике (сайт интернет-магазина)

| Атрибут | Тип | Пример значения | Обязательность |
|---------|-----|-----------------|----------------|
| customer_name | VARCHAR(100) | «Иванов Иван Иванович» | Да |
| phone | VARCHAR(20) | «+7 (999) 123-45-67» | Да |
| email | VARCHAR(100) | «ivanov@example.com» | Нет |
| address | VARCHAR(255) | «г. Москва, ул. Ленина, д. 1, кв. 10» | Да |
| birth_date | VARCHAR(10) | «15.01.1990» | Нет |
| gender | CHAR(1) | «M» | Нет |

## Структура объекта в приёмнике (OMS)

| Атрибут | Тип | Обязательность | Ограничения |
|---------|-----|----------------|-------------|
| full_name | VARCHAR(150) | Да | Не пустое |
| phone_number | VARCHAR(15) | Да | Только цифры, формат 79991234567 |
| email | VARCHAR(100) | Нет | Валидный email |
| country | VARCHAR(50) | Да | Из справочника |
| city | VARCHAR(100) | Да | — |
| street | VARCHAR(150) | Да | — |
| house | VARCHAR(20) | Да | — |
| apartment | VARCHAR(20) | Нет | — |
| birth_date | DATE | Нет | Формат ISO 8601 |
| gender_code | INTEGER | Нет | 1 — мужской, 2 — женский |

## Карта сопоставления

| Атрибут приёмника | Источник | Преобразование |
|-------------------|----------|----------------|
| full_name | customer_name | Прямое сопоставление (переименование) |
| phone_number | phone | Нормализация: удалить пробелы, скобки, дефисы, «+»; оставить только цифры |
| email | email | Прямое сопоставление; если пусто — NULL |
| country | address | Разбиение: извлечь страну (по умолчанию «Россия») |
| city | address | Разбиение: извлечь город |
| street | address | Разбиение: извлечь улицу |
| house | address | Разбиение: извлечь дом |
| apartment | address | Разбиение: извлечь квартиру |
| birth_date | birth_date | Приведение типа: строка «15.01.1990» → DATE «1990-01-15» |
| gender_code | gender | Сопоставление по справочнику: «M» → 1, «F» → 2 |

## Две потенциальные проблемы и их решения

### Проблема 1. Нестандартный формат адреса
**Описание:** В источнике адрес хранится одной строкой в свободном формате. Возможны варианты: «г. Москва, ул. Ленина, д. 1, кв. 10», «Москва, Ленина, 1-10», «Москва, ул. Ленина 1 кв 10». Разбиение на компоненты может дать ошибки.

**Решение:**
- Использовать библиотеку адресного парсинга (например, `pymorphy2` + регулярные выражения или специализированные сервисы типа DaData).
- Предусмотреть fallback: если разбиение не удалось — записывать в поле `city` всё значение, а остальные поля оставлять NULL.
- Добавить логирование нераспознанных адресов для ручного разбора.

### Проблема 2. Разные кодировки и специальные символы
**Описание:** В поле `customer_name` могут встречаться символы разных кодировок (UTF-8, Windows-1251), а также лишние пробелы, дефисы, апострофы. В приёмнике поле `full_name` имеет ограничение по длине и требует нормализации.

**Решение:**
- Привести все строки к UTF-8 на этапе извлечения.
- Выполнить нормализацию: `TRIM`, удаление двойных пробелов, замена некорректных символов.
- Проверить длину: если > 150 символов — обрезать с логированием.
- Использовать валидацию на этапе тестирования.
